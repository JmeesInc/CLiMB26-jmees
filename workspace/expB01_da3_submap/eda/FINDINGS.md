# 提出構成 (v001_da3_submap) の予測 EDA

対象: `submit/v001_da3_submap/output/`（コンテナ実出力, 全6系列）vs `expA00/colmap_gt`
スクリプト: `pred_eda.py`（誤差プロファイル+規約検証）, `rot_diag.py`（回転診断）,
`rot_smooth_test.py`（平滑化の効果測定）。図: `figs/per_frame_ate.png`

## 1. 誤差は「発散」ではなく「振動」— ドリフトは軽微
per-frame ATE は 1〜8mm（Seq_5 のみ 2〜20mm）を波打つだけで、単調な発散がない。
| seq | 前1/3 | 後1/3 | 比 |
|---|---|---|---|
| Seq_0 | 2.23 | 3.31 | 1.48× |
| Seq_1 | 2.61 | 3.52 | 1.35× |
| Seq_2 | 2.62 | 4.76 | 1.81× |
| Seq_3 | 3.54 | 4.04 | 1.14× |
| Seq_4 | 2.77 | 2.86 | 1.03× |
| Seq_5 | 6.45 | 10.30 | 1.60× |
→ ループクロージャ無しでこの水準。ORB-SLAM3 が Seq_5 で 54mm まで直線ドリフトしたのとは対照的。

## 2. チャンク連結は「継ぎ目」を作っていない（設計の妥当性確認）
ATE をチャンク位相（step=5）で層別しても差は **0.08〜0.21mm**（ATE 平均 3〜8mm に対し無視できる）。
rotation-first の重複整列は周期的アーティファクトを一切生んでいない。

## 3. 誤差はカメラ速度に連動する（← 実系列での主リスク）
Seq_0 の frame 100〜210 に高周波ジッタ帯がある。原因は **GT のカメラ速度**:
- 帯内 **0.98 mm/frame** vs 帯外 0.48 mm/frame（約2倍）
- GT の大回転（>5°/frame）とは無相関（21回中2回しか帯内に無い）

→ **速く動くほど誤差が増える**。6月EDAで実系列はsimの約3倍速い（23px vs 8px/frame）と判明しており、
**実系列では sim より明確に悪化する見込み**。ローカルCVの 4.13mm を実系列に外挿してはいけない。

## 4. RPE 回転 23° はバグではない・平滑化でも直らない（優先度低）
ATE 2.8mm と RPE_rot 23° の乖離は規約ミスを疑う典型パターンだったが、**否定された**:
- **転置（w2c 取り違え）仮説は棄却**: 転置すると 23.5°→33.6° と悪化
- **ランダムウォーク**: RPE1 3.45° → RPE40 23.3°。√40×3.45=21.8 とほぼ一致
- **時間平滑化はほぼ無効**: 窓25 でも 23.46→22.46（**4.3%のみ**）＝高周波ノイズではない
- **GT 自体がジッタを含む**: 1フレーム回転の中央値 0.21° に対し平均 2.04°、p99 26.6°、最大 98.9°。
  連続する回転軸の |cos| は 0.48（ほぼ無相関）。クリップ全体で累積 656° 回って正味 61° しか変わらない
- **全手法が同水準**: ORB-SLAM3 20.5° / 本手法 23.5° / VGGT-SLAM 25.4°。突出して悪いわけではない

→ RPE_rot は新スコアでは**タイブレークのみ**（`Score_Rot`、主指標は ATE ベース）。
   データ由来の性質で改善余地が薄く、**投資対効果が低い**。深追いしない。

## 5. その他
- **Sim(3) スケール 0.475〜0.535**（全系列）: DA3 の "metric" depth は sim 単位の約半分。
  Sim(3) が吸収するので実害なしだが、**系列間で一貫している**ことが重要で、
  これが s=1 固定連結が成立する理由の裏付けになっている
- 点群は 5/6 系列で 200k 上限に到達（Seq_4 のみ 136,837＝短いため）
- Seq_4 の TFR 62.1% は mp4 が先頭200連番しか含まないデータ由来（手法の失敗ではない）

## 結論・次の一手
1. **チャンク連結は健全**。継ぎ目由来の誤差は無く、改善余地はそこに無い
2. **速度依存性が実系列での最大リスク**。実系列は sim の3倍速い →
   chunk/overlap を速度に応じて適応させる（速い区間は overlap を増やす）のが筋の良い次の一手
3. **回転は追わない**。バグではなくデータ性質、かつタイブレーク専用指標
4. ドリフトは軽微だが Seq_5(最大変形) で 1.6× → 変形が強い区間での (t,t+k) スキップ拘束は依然有効そう

## 6. 3D 可視化・動画（`viz3d.py` → `figs/`）
全て GT 座標系（評価器と同じ Sim(3)/Horn 整列後、mm）で描画＝図の残差がそのまま ATE。

| 出力 | 内容 |
|---|---|
| `traj3d_<seq>.png` (6本) | GT(緑) vs 予測(赤)、3/4視点＋真上。**オレンジ線が per-frame 誤差** |
| `points3d_<seq>.png` (6本) | 予測点群（RGB着色＋重心距離着色）に GT 軌跡を重畳 |
| `orbit_<seq>.mp4` (Seq_0/3/5) | 点群+軌跡の周回カメラ 5秒 |
| `fly_<seq>.mp4` (Seq_0/3/5) | 軌跡をフレーム順に描画＋誤差グラフ同期表示 7秒 |

公式評価器の PLY（`--save_ply`、`line_error.ply` 等）も生成可能で MeshLab で開ける。

### 図から見えたこと
- **Seq_5(最大変形) の誤差は「系統的なズレ」ではなく「GT 周りの左右への蛇行」**。
  真上視点で予測が GT 線の左右に振れる様子がはっきり出る。§1 の「振動でありドリフトではない」を視覚的に裏付け
- 点群は大腸内腔のチューブ構造が明瞭。ただし**深度の外れ値が薄く尾を引く**（表示は上位1%を除外）。
  提出物には残るが TFR/ATE には影響しない

### 可視化の実装メモ
matplotlib の 3D アニメーションは**フレーム数ではなく点数**が描画時間を支配する
（毎フレーム scatter を再描画するため）。40k点では事実上完了せず、動画用は 6k点に削減して 2分/本に短縮。
