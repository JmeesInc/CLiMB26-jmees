# expB02_fisheye — v001 LB 破綻 (ATE 28.3 vs CV 4.13) の原因切り分け

## 目的
LB rank 7/7 の主犯仮説「実系列の Kannala-Brandt kb4 魚眼を pinhole 前提の
DA3 パイプラインに素通ししたことによる幾何破綻」を sim 上で定量検証し、
undistort 前処理(v002 候補)の効果を測る。

## 設計: 2×2 対照実験（sim, chunk8/ov3/s=1, 公式評価器）
| config | 入力 | 前処理 | 期待 |
|---|---|---|---|
| A | pinhole sim（既存 expB01 results_s1） | なし | 基準 3.11(Seq_0)/8.39(Seq_5) |
| B | **合成 kb4 魚眼** | なし | 仮説が真なら 25mm 級へ破綻 |
| C | 合成 kb4 魚眼 | **rectify(逆写像)** | A へ回復 |

- 魚眼合成: Endoscope_01 実キャリブ(1440×1080, fu=717.7, kb4=[-0.1397,...]) を
  2/3 スケールで sim 960×720 へ適用（kb4 係数は θ のみの関数で解像度非依存）。
  `cv2.fisheye.undistortPoints` で出力画素→pinhole 元画素の逆マップ → remap。
  sim の半画角 45.5° を超える画素は黒 = 実機の円形黒枠を再現（被覆 52%）
- rectify: `cv2.fisheye.initUndistortRectifyMap`。**P=sim K（既知の真値）**で合成の
  完全逆写像になる（roundtrip PSNR 34.6dB / valid 100%）。実データ用には
  `--p_mode auto`（estimateNewCameraMatrix, balance）だが、auto は合成データでは
  framing が破綻（cx=667, 黒帯 46%）するため 2×2 では sim モードを使う
- 実行: `STAGE=prep|slam|eval bash run.sh`, SEQS="Seq_0 Seq_5"（速度優先の subset）。
  iMED venv + GPU0。`DA3_PRECISION=fp16`（Turing の bf16 エミュ回避で 4.2 倍速）

## 並行监査: コンテナバグの線の潰し込み（ユーザー指摘対応）
- **S1 デコードずれ → シロ確定**: 実 .mov (Seq_001, h264 1440×1080 40fps CFR) から
  ffmpeg 再エンコードで 30s クリップ作成 → ffmpeg 全展開 vs cv2 逐次デコードを
  フレーム 0/1/100/599/1199 で画素比較 → **全点 MAD=0.000・フレーム数一致・オフセットなし**。
  metadata count == decoded count。予備の ±1 オフセット探索でも 0 が最良
- predict.py 精読: sim 検証済みロジックと同一。チャンク失敗時の「前ポーズ保持」
  フォールバックはあるが TFR 100 と整合する範囲。残る非バグ要因は
  実クリップ長（~1200frame = sim の4倍 → 連結ドリフト増）とドメイン差
- 40fps 判明（fps=50 と推定していた LB 逆算は要再計算: W_t 境界 T≤0.025 s/frame に緩む）

## 結果（2026-08-29 確定）— 仮説 CONFIRMED
| config | Seq_0 ATE | Seq_5 ATE | Mean | RPE_rot(δ40) |
|---|---|---|---|---|
| A pinhole 基準 (expB01 s=1) | 3.11 | 8.39 | 5.75 | ~24° |
| B 魚眼素通し | 17.83 | 21.83 | **19.83 (×3.5)** | **36.0°** |
| C 魚眼→rectify | 2.83 | 8.31 | **5.57 (完全回復)** | 24.0° |

- **B の破綻パターンが LB 実測 (ATE 28.3 / rot 34.0°) とほぼ一致**（特に回転 36 vs 34）
  → v001 の LB 惨敗は魚眼素通しが主犯と確定。残差 (19.8 vs 28.3) は実クリップ長
  （~4倍→連結ドリフト）・速い動き・液体等の実ドメイン差で説明圏内
- C は A を僅かに上回りさえする（境界の黒枠画素が conf フィルタで落ち、
  むしろクリーンになった可能性）
- **v002 = rectify 前処理**（balance=0, cv2.fisheye）で確定。TFR は B でも 100 だった
  = TFR は魚眼に不感、ATE/rot のみが壊れる（LB で TFR 100 だったことと整合）

## v002 回帰テスト（合成魚眼 mp4 → v002 predict.py, 公式評価器）
| 版 | Seq_0 | Seq_5 | Mean | 学び |
|---|---|---|---|---|
| rectify のみ (auto-P) | 16.05 | 14.94 | 15.49 | **auto-P は画像内黒枠を知らず 46% 黒帯** → ほぼ効果なし |
| + 貪欲クロップ | 16.05 | 14.94 | 15.49 | 貪欲成長が縦→横の順で詰み crop=None（幅28pxの局所解） |
| + **正確な最大内接矩形** | 6.27 | **8.27** | **7.27** | **回復**。Seq_5(正確キャリブ) 8.27 ≈ C の 8.31 = 完全一致 |

- **キャリブ選択の感度（確証済）**: Seq_5=Endoscope_01(正確) は C 水準まで完全回復、
  Seq_0=平均キャリブ fallback は 6.27 (C 2.83 比 +3.4mm)。DA3_FORCE_ENDO=1 で Seq_0 を
  正確キャリブ再実行 → **3.35mm**（pinhole 基準 3.11 と同水準）。**per-seq 正確キャリブで
  魚眼劣化はほぼ完全に打ち消せる**。平均 fallback でも素通し比 3〜4× 改善
- クロップは「rectify 後初フレームの端接続暗領域 flood-fill → 最大内接矩形（ヒストグラム法, 0.7s×1回）」。
  実 1440×1080 フレームは balance=0 で全有効 → crop no-op を確認済み

## 実クリップでの定性検証（Seq_001 30s@40fps, GT 無し）
`scripts/plot_real_traj.py`（軌跡 3D + per-frame ステップ長）。v002 は `Seq_001_a` から
Endoscope_01 を正しく選択、crop は no-op（実 1440×1080 は balance=0 で全有効）、1200/1200 ポーズ。

| | ステップ長 median | p99 | 軌跡の広がり | 見た目 |
|---|---|---|---|---|
| v002 rectified | **0.0199** | 0.319 | [5.9, 2.9, 9.1] | 滑らかで一貫した前進軌跡 |
| 素通し (v001 相当) | 0.0708 (**3.6×**) | 1.170 (3.7×) | [8.7, **17.0**, 13.4] | ジグザグに暴れて発散 |

→ **GT の無い実データでも rectify の効果が明確**。素通しはフレーム間ジャンプが恒常的に大きく、
LB の ATE 28mm / rot 34° と整合する挙動。図: `figs/real_traj_compare.png`

## 実データ rectify の設計（v002 へ）
- balance=0 が黒帯ゼロで最良（0.4 で波状黒枠、1.0 は星形で不可）
- キャリブ 18 本はクラスタ内 ±1〜2% と均質（01-10: fu≈725, 11-18: fu≈785, k1≈-0.12 共通）
  → テストクリップ名から `Seq_(\d+)` が読めれば `_info.json` 対応表で正確に、
  読めなければ全 18 本平均の代表キャリブで undistort（DA3 が焦点は自己推定するので
  除去すべきは非 pinhole 歪み形状のみ）
- ローカル sim 回帰テストは pinhole 入力なので `DA3_RECTIFY=0` で無効化できるようにする
