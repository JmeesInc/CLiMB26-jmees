# expB06_posecond — DA3 姿勢条件付き推論で窓間スケールを拘束する（B案）

## 動機（daily 8/30 §7）
- §14.1: 窓ごとスケール補正に **37% の伸びしろ**（held-out）。§14.2: 局所信号では予測不能。§14.3: 長スパン窓は系列依存で不採用
- **DA3 は姿勢条件付き推論（Pose-Conditioned）を持ち、我々は未使用だった**。
  `inference(extrinsics=, intrinsics=)` → `CameraEnc` が (T, quat, fov) をトークン化し backbone の各ビュー先頭スロットへ注入。
  未指定時は学習済み `camera_token`（ref/src）が同じスロットに入る
- nested の metric 枝は常に無条件の単眼 → 窓スケールは「単眼 metric のばらつき」任せ。これが不整合の源泉
- 条件付けなら窓スケールは「重複カメラの既知ベースライン」で決まる = **予測でなく拘束で解く**

## 実装（`scripts/predict_cond.py` = v003 predict.py + 差分）
| env | 内容 |
|---|---|
| `DA3_COND=twopass` (B1-lite) | 無条件推論→現行連結→全 N ビューの大域姿勢 + 既知 rectify 後 K を条件に再推論、`align_to_input_ext_scale=False` で整列済み予測姿勢を読み新規ビューを置換。**改造なし** |
| `DA3_COND=partial` (B1-partial) | `cond_partial_pass()`: 既知（重複）ビューだけ `cam_enc` トークン、新規ビューは学習済み src トークンの**混在**。`net.cam_enc` を一時差し替え。出力を既知ビュー上の Sim(3) で大域へ。**学習時に混在は未経験＝賭け** |
| `DA3_PHASE=k` (B3) | 窓開始を k キーフレームずらす。`scripts/merge_phases.py` で位相 0/3 の連鎖を Sim(3) 整列後に平均 |
- 既知 K: `build_rectify_maps` が pinhole `P` も返すよう変更（crop 分を主点から引く）。DA3 の input_processor が画像と一緒に K をリスケールするので**原寸で渡す**
- 診断ログ `cond pass: new-view centre shift X / shared Y (x window extent)`: X≈0 なら「エコー」（条件付けが姿勢を変えていない）、>0 なら「洗練」

## 落とし穴（このセッションで踏んだ）
- `predict.py` は同ディレクトリの `calib_table.py` を import する → コピー先にも置く
- バックグラウンド起動で **cwd がずれると相対 `cd` が静かに失敗**し、古いログを読んで誤判断する → 絶対パス必須

## 結果
### B3 位相平均 — 不採用（`results/ph3_c12o6_s6.json`, `ph03avg_c12o6_s6.json`）
| | 001_a | 001_c | 003_a | 003_b | MEAN |
|---|---|---|---|---|---|
| 位相 0（= v003） | 6.85 | 2.49 | 3.45 | 4.70 | **4.374** |
| 位相 3 | 7.10 | **6.08** | 3.19 | 4.29 | 5.165 |
| 平均 | 6.77 | 3.66 | 3.31 | 4.38 | 4.530 |
- 3/4 系列で平均が勝つが 001_c で位相 3 が崩れ（2.49→6.08、×2.4）、平均を引きずる
- **窓境界を 3 キーフレームずらすだけで 2.4 倍振れる** → 窓スケール誤差は拡散ノイズでなく
  **特定の悪い窓に集中**（どのフレームが同じ窓に入るかで決まる）。単純平均では救えない。
  頑健化（不一致の大きい区間で片側を捨てる）は可能だが、根本は「悪い窓を作らない/検出する」こと
### B1-lite 初版の失敗（バグ、結果無効）
- `api.inference(align_to_input_ext_scale=False)` は `align_poses_umeyama(ext_ref=予測, ext_est=入力)` を呼び、
  **入力姿勢を予測の正規化座標系に写して返す**（予測を入力座標系に戻すのではない）。
  新規ビューだけ別座標系になり軌跡が壊れる。診断「共有ビューが 2×窓幅動く」で発覚
- 修正: API の整列を経由せず内部経路（preprocess→cam_enc→forward→convert）で生の条件付き予測を取り、
  自前 Sim(3) で大域へ（`cond_partial_pass(..., replace_known=True)`）
### 実装の落とし穴（追加）
- `camera_token` は `net.backbone.pretrained`（DinoV2 ラッパーの内側 ViT）にある
- `nn.Module` の子モジュール属性に lambda は代入不可 → `_ConstToken(nn.Module)` で包む
### B1 姿勢条件付き — 両変種とも不採用（`results/cond2p_c12o6_s6.json`, `condpart_c12o6_s6.json`）
| | 001_a | 001_c | 003_a | 003_b | MEAN ATE | rot40 | 診断（新規ビュー移動 ×窓幅） |
|---|---|---|---|---|---|---|---|
| 基準 c12o6_s6 (v003) | 6.85 | 2.49 | 3.45 | 4.70 | **4.374** | 5.18 | – |
| twopass（全ビュー条件付け） | 6.79 | 2.48 | 3.41 | 4.61 | 4.323 (−1.2%) | **4.77 (−8%)** | 0.03〜0.06 = **エコー** |
| partial（混在トークン） | 8.26 | 8.58 | 10.21 | 6.35 | **8.349 (×1.9)** | 6.99 | 0.9〜2.5 = **破綻** |
- **twopass**: 姿勢ヘッドは与えた姿勢をほぼそのまま返す（移動 3〜6% 窓幅）。ATE −1.2% は CV ノイズ（SE ±0.75）以下。
  回転 −8% は実在しそうだが、現順位では tie-break 圏外（CCLAB/Unal と 5% 以内でない）で、コスト 2×（評価機 0.032 s/f → W_t≈1.3）に見合わない
- **partial**: 学習時に見ていない「既知/未知トークン混在」は分布外で、新規ビューが 1〜2.5 窓幅も飛ぶ。4/4 系列で悪化。**即却下**
- 結論: **DA3 の姿勢条件付けは深度整合のための機構で、姿勢の洗練には使えない**。
  README の "superior depth consistency when poses are provided" の文言どおり、姿勢側は入力に従属する

## B案トラックの総括
| 案 | 結果 | 判定 |

| B1-lite 全ビュー条件付け | 4.323 / rot 4.77（2×コスト） | 不採用（エコー） |
| B1-partial 混在トークン | 8.349 | 不採用（分布外破綻） |
| B3 位相平均 | 4.530 | 不採用（悪い窓に引きずられる） |
| §14.3 長スパン窓（expB05） | 系列で二分 | 不採用（汎用性なし） |
現行アーキテクチャ（DA3 窓連結）の周辺で、v003 (4.374) を有意に超える構成は見つからなかった。
**唯一の実在する伸びしろ「悪い窓」**（位相 3 ずらしで 001_c が 2.49→6.08）は、局所信号では検出できず（§14.2）、
条件付けでも潰せず、平均でも消えない。残る手は「複数位相の中央値」だが 3× コストで W_t の崖を越える。
