# v003_da3_stride — DA3 submap SLAM + kb4 rectification + キーフレーム stride

**v002 との差分は 1 点のみ**: DA3 を **6 フレームに 1 回**だけ走らせ、
間のポーズはカメラ中心を線形補間・姿勢を SLERP で埋める。
出力は全フレーム分なので **TFR 100 を維持**。rectify・連結・出力形式は v002 と同一。

## 背景（なぜ stride か）

v002 LB: climb 23.644 (rank 6/7) = ATE 15.762 / rot 7.335° / TFR 100 / 0.077 s/frame。

- **生 ATE なら 4 位相当**（PRISM 10.69 < EndoNav 11.18 < CCLAB 11.24 < **我々 15.76** < Unal 16.47）
- しかし `climb / ATE = 1.5001` = **W_t が満額 1.5**（速度ペナルティ）。W_rtf は 1.0（TFR 100 で満点）
- つまり **順位差は全部速度**。速度だけ直せば climb 23.644 → 15.762 = rank 3〜4

さらに **想定外の収穫**があった。stride は速度だけでなく **ATE も大きく下げる**:
実クリップ 4 本で **9.301 → 5.735 (−38%)**。

### なぜ stride が ATE を下げるのか
DA3 submap の誤差は**ドリフトではない**（Horn 整列後の毎フレーム誤差の後⅓/前⅓ 比が
0.18 / 0.98 / 0.34 / 0.39 = 序盤に大きく後半で減衰する低周波うねり）。
真因は**窓間スケールの不整合**で、「DA3 深度はメトリック → 窓間スケール = 1」という前提が
sim では真だが実データでは偽（重複が示唆する s は 0.34〜2.78、|s−1| median 0.20、累積積 0.0143）。
**stride を上げると窓数が減り、不整合の累積回数が減る。** 加えてキーフレーム間ベースラインが
伸びて DA3 の三角測量条件が良くなる。

詳細な測定は `daily_reports/20260829.md` §11-12。

## 実装
1. **キーフレーム抽出**: `kf = range(0, n, STRIDE)`（末尾フレームを必ず含める）。
   非キーフレームは `cap.grab()` でデコードごとスキップ（`VideoWindow`）
2. **DA3 + 連結**: キーフレーム列に対して v002 と同一の submap chaining
3. **補間** (`interpolate_poses`): カメラ**中心**を線形、**姿勢**を SLERP で全 n フレームへ展開
4. `DA3_STRIDE=1` で v002 と同一経路（回帰テスト用）

## stride の選択（実クリップ sweep）

| stride | Seq_001_a | Seq_001_c | Seq_003_a | Seq_003_b | **MEAN ATE** | rot40 | s/frame (RTX8000) |
|---|---|---|---|---|---|---|---|
| 1 (= v002) | 21.99 | 3.78 | 5.27 | 6.16 | 9.301 | 6.56° | 0.288 |
| 2 | 11.65 | 3.40 | 4.82 | 5.16 | 6.257 | 6.16° | 0.147 |
| 4 | 11.46 | 3.71 | 3.39 | 4.47 | 5.756 | 5.82° | 0.077 |
| **6 ←採用** | 11.30 | **2.78** | 3.90 | 4.96 | **5.735** | **5.55°** | **0.051** |
| 8 | 15.21 | 2.81 | 3.65 | 4.57 | 6.558 | 5.46° | 0.039 |
| 12 | 10.98 | 6.78 | 3.19 | 4.65 | 6.398 | 6.64° | 0.027 |

TFR は全設定 100.00 / 4-4。**1→4 で急改善、4〜6 で底、8 以上で崩壊**の U 字。

**stride 6 を採用した理由**:
- ATE / rot ともに最良（5.735 / 5.55°）
- **W_t マージンが厚い**。評価機 RTX5090 は本機の約 3.7×（v002 stride1 が本機 0.288 → 評価機 0.077）
  → stride 6 は評価機で **~0.015 s/f**。境界 0.025（40fps）に対し余裕が大きい。
  stride 4 は ~0.021 で余裕が薄く、テスト系列次第で境界を跨ぐリスク

## 棄却した施策（すべて実測で否定）

| 施策 | 結果 |
|---|---|
| GT 準拠 Endoscope_07 キャリブを強制 | 9.525 vs 現行 9.301 → **現行が良い**。キャリブ選択は二次要因 |
| 窓ごと focal 正規化 | `corr(log s, log f比) = +0.088` ≒ 無相関。残差も 0.436 vs 生 0.359 と悪化 |
| 重複からの窓間スケール推定 | fixed1 5.756 が最良（damped α=.25/.5/1 → 5.760/5.798/5.839、raw → 6.748） |
| ポーズグラフ / ループクロージャ | 誤差がドリフト型でないため効かない。未実装のまま優先度を下げた |

`DA3_SCALE=fixed1|damped|overlap` は ablation が再現できるよう `predict.py` に残してある（既定 `fixed1`）。

**速度**: コンテナ 0.055 s/frame @ RTX8000 fp16（実クリップ）。評価機 RTX5090 換算 ~0.015 s/f。

**予想 LB**: climb ≈ 15.762 × 0.617 × 1.0 ≈ **9.7**。
ただし実 CV は 4 クリップのみで **Seq_001_a (11.30) が外れ値**（他は 2.8〜5.0）。
W_t 1.5→1.0 の分（−33%）は速度実測に基づき確度が高いが、ATE 改善分（−38%）は幅を持つ。

## 使い方
```bash
bash build.sh                                    # DA3 ソース + 重みを焼き込んでビルド
bash test.sh                                     # sim 回帰（既定）
DA3_STRIDE=1 DA3_RECTIFY=0 bash test.sh          # v001/v002 との後方互換確認
SYNAPSE_PROJECT_ID=syn######## bash export.sh    # レジストリ用にタグ付け（push は手動）
```

環境変数: `DA3_STRIDE`(6) / `DA3_RECTIFY`(1) / `DA3_RECT_BALANCE`(0) / `DA3_FORCE_ENDO` /
`DA3_PRECISION`(auto) / `DA3_SCALE`(fixed1) / `DA3_SCALE_ALPHA`(0.5) / `DA3_SCALE_CLAMP`(1.15)

**評価機要件**: RTX 5090 = sm_120 のため **cu128 wheel 必須**。`--network=none` で走るので
重みはビルド時にイメージへ焼き込み済み。ピーク GPU メモリ 19.3GB @ chunk8/res504。
